# 提交信息规范（Commit Convention）

> 本文档定义 DBox 仓库 commit message 的唯一规范，所有提交均须遵守，
> 由 CI / 评审按此格式检查。目标：一眼能看出「改了哪类东西、动的是哪个模块」，
> 历史可检索、可生成变更日志，且不再出现 `修：` / `新增：` / `P0-2` / `[继续]`
> 这类混入 subject 的噪声。

---

## 1. 格式

```
<type>(<scope>): <subject>

[可选的 body：说明为什么改、背景、影响范围]

[可选的 footer：Refs #123 / BREAKING CHANGE: ...]
```

- **type**：必填，英文小写，见下表。
- **scope**：必填（无合适 scope 时用 `misc`），英文小写，标识受影响的模块。
- **subject**：必填，简明中文或英文，**动词开头**，不写句号，不加方括号，
  不出现 `修：` / `新增：` 这类前缀、不出现 `P0-2` 之类优先级标签。

---

## 2. type 取值

| type | 含义 | 示例 |
|------|------|------|
| `feat` | 新功能 / 新能力 | `feat(library): 增加扫描预演与一键撤销入口` |
| `fix` | 缺陷修复 | `fix(ui): 图集出现重复的「筛选」按钮` |
| `refactor` | 重构，行为不变 | `refactor(task): 重试迁移至能力注册表` |
| `perf` | 性能优化 | `perf(proxy): 媒体代理改为事件通知，去掉轮询` |
| `docs` | 仅文档 | `docs: 补充插件架构契约说明` |
| `test` | 仅测试 | `test: 新增扫描预演异常判定单测` |
| `chore` | 构建/依赖/杂务 | `chore: 升级 requests 至 2.32` |
| `style` | 仅格式（不影响逻辑） | `style: 统一 imports 排序` |
| `build` | 构建系统 | `build: 调整 CI 测试矩阵` |
| `ci` | CI 配置 | `ci: 将 test_scan_preview 接入流水线` |

---

## 3. scope 常用取值

| scope | 覆盖范围 |
|-------|----------|
| `db` | 数据库 / 迁移 / 快照 / 备份 |
| `task` | 统一任务框架 / 能力注册表 / 续跑 |
| `library` | 资源库 / 扫描 / 索引 / 回收站 |
| `migration` | 启动迁移 / schema 版本 |
| `home` | 首页聚合 / 筛选栏 |
| `ui` | 通用前端组件 / 嵌入视图几何 |
| `api` | 后端接口（无更具体模块时） |
| `plugin` | 插件（尽量再写具体插件 id，如 `plugin/x`） |
| `thumb` / `dl` | 缩略图 / 下载器 |
| `misc` | 实在无法归类的兜底 |

---

## 4. 正文（body）与脚注（footer）

- body 可选，回答「为什么改」「影响范围」，每行建议不超过 72 字符。
- 优先级（P0/P1…）**只写在 body 或 PR 描述里**，不要进 subject：

  ```
  fix(library): 扫描判缺失时改为移入回收站而非硬删

  P0：避免盘未挂载好时被误判为文件丢失而瞬时硬删。
  判定缺失仅标记 in_trash，超期才真正清理。
  ```

- footer 可写 `Refs #123` 或 `BREAKING CHANGE: <说明>`。

---

## 5. 正反例对照

| ❌ 不规范 | ✅ 规范 |
|-----------|---------|
| `修：增量扫描把"未枚举到"当成"文件已删除"` | `fix(library): 增量扫描误将未枚举当已删除` |
| `新增：数据库自动快照与恢复（数据安全 P0）` | `feat(db): 增加数据库自动快照与一键恢复` |
| `数据安全 P0-2：扫描触发的删除改为「移入回收站」` | `fix(library): 扫描判缺失时改为移入回收站而非硬删` |
| `扫描预演（只读）与撤销入口` | `feat(library): 增加扫描预演（只读）与一键撤销入口` |
| `[继续] 长任务中断后可继续…` | `feat(task): 支持长任务中断后继续（重启回收僵尸任务）` |

---

## 6. 约定小结

1. subject 必须 `<type>(<scope>):`，英文 type + 小写 scope；
2. 不写 `修：` / `新增：` / `P0-2` / `[继续]` 这类前缀或标签进 subject；
3. 描述动词开头、简洁、无句号；
4. 优先级、背景放 body；
5. 一次提交只做一类事，能拆就拆，便于 revert 与 bisect。
